# JIT 与 XPOST 的调用约定

本文只记录当前代码里的约定。它不是固件已经执行过 JIT 镜像的证明。

## 入口

固件在 `inner_xdp` 里用 `jalr` 进入槽位首地址。`a0` 是 `xdp_md *`。返回值只取 `a0` 的低 32 位。

JIT 序言把 `a0` 当作 BPF `R1` 的低半，并把 `R1` 的高半清零。退出时 `R0` 放在 `a0` 和 `a1`。固件忽略 `a1`。

`xdp_md` 的前两个字段是 `data` 和 `data_end`，各 4 字节，小端。

## 栈

`frame_bytes()` 当前是 592。其中 BPF 栈是 512 字节。其余是保存的寄存器和临时槽。

这些字节从调用方的 `sp` 往下分配。JIT 不切换到另一条栈。592 没有和固件剩余栈空间对过。

## helper

`helper_dispatcher` 是 ilp32 函数。`a0` 是 helper 编号。`a1` 到 `a5` 是 BPF `R1` 到 `R5` 的低 32 位。返回值在 `a0`，JIT 把它零扩展进 `R0`。

调用点在链接前是 `lui t1, 0; jalr ra, t1, 0`。`link` 把这对指令改成 `helper_dispatcher` 的绝对地址。编号在 `a0` 里，不在地址里。

BPF 到 BPF 的调用直接拒绝。尾调用拒绝。

## map

`lddw` 链接进去的是 map 的 VMR 地址，不是 value 的存储地址。地址 0 会拒绝。

主机差分测试在 VMR 处放一个 `MAP1` 描述符，value 放在描述符里的 `storage`。这不是固件的别名表。固件用 VMR 地址查自己的表。

没有写完的重定位不会被 `link` 或 `check` 当成可执行镜像。

## 内存和算术

半字、字和双字访问都拆成字节读写。eBPF 允许不对齐的地址。`lw` 和 `sw` 在 2 模 4 的地址上没有作为 JIT 输出。

32 位 ALU 的结果零扩展。除以 0 得到 0。32 位模 0 保留低 32 位并清高 32 位。移位计数对 32 位取低 5 位，对 64 位取低 6 位。这是 RFC 9669 第 4 节的规则。

有符号除法里，最小负数除以 -1 使用绕回除法。RFC 9669 的表没有给这个溢出单独命名。

ALU64 的除法和取模、ALU64 字节交换、原子操作、以及 `jmp32` 的 `ja`、`call`、`exit` 都返回错误。

## 不由 JIT 保证的事

PREVAIL 通过只说明 eBPF 字节码过了那个检查器。它不检查 RV32 布局、槽位长度或 helper 地址。

eBPF verifier 不验证链接脚本。入口可执行、槽位容量和 ctx 边界由固件和打包步骤负责。本文件不把这些写成已经在板上测量过的事实。
