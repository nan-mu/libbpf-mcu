The real generated Ninja graph has SHA-256 `b910dbc1aa950b02e8de0d57a5b11ea50ff9a7ae83a73460bf907f60f68c3c83`. The command expansion and DOT graph have SHA-256 `42d2b66629cff29e7f36f98814619a23ac63ed5372ae5729e3616036afa38204` and `722e4b5ddefa6862f19e328e048d2bd3a57153162c99ed435cf569ee5ffcb9b2`.

```text
C + BPF SDK -> raw object + bpf.d -> PREVAIL -> indexed BPF object
   |                                          |             |
   +-> exact source copy, ordered after gate   |             +-> JIT pair
   +-> RV32 compile + rv32.d -> SDK check -> reference .o     |
                                LLD at zero -> AOT pair <----+
                                      canonical AOT layout -> rBPF pair
verified BPF and linked AOT -------------------> objdump
JIT/rBPF pairs -> persistent adapter ELFs -----> objdump
Ninja graph -> recipes.txt
source + disassembly + image bytes + recipes -> report -> index
```

The private tree retained `bpf.d`, `rv32.d`, both raw objects, `zero.ld`, linked AOT ELF, JIT and rBPF report ELFs, the four objdump texts and `recipes.txt`. The [reference graph test](https://gitea.nas.nan-mu.cc/mcp/libbpf-mcu/src/commit/4f1a5df8ddb16aa026c68198f0f126bfe46e0524/tests/ninja-example-static.md) used Ninja 1.12.1 and mock edges. Its observed no-op, verifier-only recompilation behavior and listing repair established reference scheduling. The actual graph evidence above tests the production chain.
