At XPOST `246d0427124f5b543ff2c536ec10e3270cbe67b5`, `ReleaseArchive::deployment_inner` in `release.rs` expects a fixed Compact ELF row and validates the embedded address and program. `deployment.rs` checks XPM1, capacity, identity and helper, then rejects mismatched native slots unless verified Case evidence applies. The subsequent XPOST PR must select the portable row, validate its member digests and image contract, bind from the actual XPM1 and selected slot, encode the result through xpost-elf, and exercise the real Agent deployment and hardware paths. The portable release deliberately changes the inputs to those old entry points.
